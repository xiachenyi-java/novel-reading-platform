【这份东西是什么】
  不是八股合集，是**你自己项目里真实发生过的技术追问**。

  每题都长这样：
    Q  面试官怎么问
    A  你怎么答（带项目里的真实细节和数据）
    ★  加分点 / 陷阱
    追问  他往下会问什么

【和《简历能力.txt》的分工】
  简历能力.txt    → 简历上怎么写、怎么把项目讲成故事（面向"包装"）
  面试题库/       → 被追问时怎么答、答到什么深度（面向"防御"）

【和《知识笔记》的分工】
  知识笔记/       → 原理是什么（学的时候看）
  面试题库/       → 被问到时怎么组织语言（面试前看）

【★ 核心原则】
  只收录**你真的做过、真的验证过**的题。
  没做过的宁可写"未做"，也不要编 —— 编的答案经不起追问。

--------------------------------------------------------------------------------
  一·一、★ 每题六栏固定格式（2026-10-06 统一）
--------------------------------------------------------------------------------

    ### Q: 一句话题目
    - **考点**：这题在考什么能力（不是"考什么知识"）
    - **追问链**：Q1 → Q2 → Q3（面试官怎么一层层往下挖）
    - **参考答案**：怎么组织语言
    - **本项目的证据**：具体文件 / 实测数据 / 故障演练结论   ★ 最值钱
    - **坑**：容易答错的地方
    - **关联**：docs/知识笔记/xxx

  ★ **为什么「本项目的证据」这一栏最重要**
    它是区别「背过八股」和「真做过」的地方。
    没有证据的题，宁可删掉也不要编 —— 编的答案经不起追问。

  ★ **「追问链」是第二重要的**
    面试不是一问一答，是一路往下挖。
    标出"下一层问什么"，才知道自己该准备到多深。

################################################################################
  二、怎么用这份题库
################################################################################

  【平时】
    每做完一件事（改完一个 bug、做完一次实验、踩完一个坑），
    问自己一句："这件事面试官会怎么问？"
    能问出题，就追加进对应分类。

  【面试前 3 天】
    只看每题的 Q 和 ★，不看 A。自己先答一遍，答不上再翻 A。

  【面试前 1 天】
    只看「四、高频追问排行」和每题的「追问」行 ——
    那是面试官真正会挖的地方。

  【面试后】
    ★ 把被问到但没答好的题补进来。这是这份文档最有价值的更新来源。


################################################################################
  三、怎么写一条新题（模板）
################################################################################

  ------------------------------------------------------------------
  Q7：面试官的原话大概是什么？
  ------------------------------------------------------------------

  A：你的回答。要求：
     · 第一句给结论
     · 中间给项目里的**真实细节**（类名、配置项、数字）
     · 最后给"我怎么验证的"

  ★ 加分点：
     · 能体现"我不只知道怎么做，还知道怎么验证"的地方
     · 能体现"我知道这个方案的局限"的地方

  ⚠ 陷阱：
     · 容易被问倒的地方

  追问：
     → 面试官往下会问什么？（这是拉开差距的地方）


################################################################################
  四、高频追问排行（★ 面试前只看这一节）
################################################################################

  【S 级 · 一定会被追问到底】

  1. 你说的"缓存降级"，怎么证明它真的生效了？
     → 题库 01 · Q5
     ★ 90% 的人答不上。因为大部分人从来没验证过。

  2. 我看你用了不少注解（@Cacheable / @Transactional），
     如果改成手写 API 会怎样？
     → 题库 01 · Q8
     ★ 这题考的是"你知不知道注解背后是切面"。

  3. 你的压测数据里 P50 为什么会是单请求的 3 倍？
     → 题库 02 · Q6
     ★ 考的是"你会不会看数据，而不是只贴数字"。

  【A 级 · 高频，答好加分】

  4. Redis 挂了，你的接口会怎样？
     → 题库 01 · Q4 / Q6

  5. 你怎么验证一个改动真的生效了？
     → 题库 02 · Q1

  6. 缓存穿透、击穿、雪崩的区别？分别怎么防？
     → 题库 01 · Q1 / Q2

  7. 跨进程调用为什么必须设超时？
     → 题库 01 · Q9

  【B 级 · 中频】

  8. 哪些地方该降级、哪些不该？
     → 题库 01 · Q12

  9. 缓存写失败为什么比读失败更难发现？
     → 题库 01 · Q11

  10. 你怎么保证压测结果可信？
      → 题库 02 · Q2

################################################################################

  这些东西的价值在于：**有数据、可复现、别人编不出来**。

  Lettuce 断连缓冲写命令        Redis 重启后 key 自动出现     实战 05 · 4.5

  ★ 用的时候注意：**数字要能解释**。
    面试官问"1.01 秒是怎么来的"，你要能答"两个 500ms 超时串行叠加"。
    只背数字不背推导过程，一问就露馅。
