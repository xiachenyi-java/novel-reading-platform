【做得好的地方（面试可以主动讲）】

  ✓ 第 1 步：从 KEYS 到 Hash 的思路值得记录
     "不要用遍历去解决一个设计问题，要换数据结构让它自然成立。"
     KEYS 是 O(N) 会阻塞 Redis，生产环境是事故级操作。

  ✓ 第 3 步：两次查询合并成一次，同时消除了并发窗口
     原写法"先判断存在，再查询"，两次查询之间用户可能被删除。
     合并成 orElseThrow 后：代码更短 + 性能更好 + 更安全。
     这是"代码质量的核心价值"的典型例子。

  ✓ 第 4 步：业务异常用 warn（不带堆栈），系统异常用 error（带堆栈）
     日志分级清晰，便于线上排查和告警分级。

  ✓ 第 2 步：路径校验用 normalize + startsWith
     先把 ../ 解析掉再判断是否在允许目录内，是标准做法。

【✅ 已解决：JacksonConfig 已删除（第 6 步）】

  ★ 2026-10-05 核实：config/JacksonConfig.java **文件已不存在**，
    在 commit 8edf2ac「修复json的版本问题」时被清掉。

  当时的原理记录（留着当知识，面试会问）：
    原来的写法是：
      @Configuration
      public class JacksonConfig {
          @Bean
          public ObjectMapper objectMapper() {
              return new ObjectMapper();          // ← 裸的，没注册任何模块
          }
      }
    问题链：
    ① Spring Boot 的 JacksonAutoConfiguration 带 @ConditionalOnMissingBean，
       "用户没自定义我才创建"
    ② 自己定义了 → Boot 那套配好的 ObjectMapper 就不生成了
    ③ 于是丢掉了：JavaTimeModule（LocalDateTime 序列化）、
       WRITE_DATES_AS_TIMESTAMPS=false、FAIL_ON_UNKNOWN_PROPERTIES=false 等
    ④ 用裸 ObjectMapper 序列化 LocalDateTime 默认会抛异常

  ★ 现在的状态：UserService 注入的 tools.jackson.databind.ObjectMapper
    是 Boot 自动配置的 Jackson 3 实例（Boot 4.x 已换到 Jackson 3），
    不再是裸的。

  ★ 通用修法（三选一，以后遇到类似情况用）：
    方案A（推荐）：直接删掉自定义类，让 Boot 自动配置生效 ← 本次选的就是这个
    方案B：用 Jackson2ObjectMapperBuilderCustomizer 扩展而不是替换
    方案C：@Bean ObjectMapper objectMapper(ObjectMapper defaultMapper)
            { return defaultMapper.copy().setSerializationInclusion(...); }

N1  ★ 黑名单过期判断的边界不一致
--------------------------------------------------------------------------------
  位置：config/LoginInterceptor.java
    游客路径（约 69 行）：  if (expireAt >= System.currentTimeMillis())
    严格路径（约 116 行）： if (expireAt >  System.currentTimeMillis())

  【问题】两处做的是同一件事（判断 token 在不在黑名单），
          但一个用 >=，一个用 >。

  【后果】当 expireAt 恰好等于当前毫秒时，两条路径行为不同：
            · 游客路径 → 当作"已过期"，删除后放行
            · 严格路径 → 当作"仍在黑名单"，返回 401
          毫秒级窗口，实际影响很小。但"同一逻辑两处实现不一致"
          是将来埋 bug 的典型位置。

  【修法】统一成一个私有方法，两处共用：
            private boolean isBlacklisted(String hashKey, String token)

  【验证】构造一个 expireAt = 当前毫秒 的 token，两条路径行为应一致。

N2  passwordHash 被写进 Redis 缓存
--------------------------------------------------------------------------------
  位置：service/UserService.java 的 getCurrentUser，第 4 步

    String json = objectMapper.writeValueAsString(dbUser);
    stringRedisTemplate.opsForValue().set(key, json, 30, TimeUnit.MINUTES);

  【问题】dbUser 是从数据库查出来的完整实体，passwordHash 还在里面。

  【后果】BCrypt 哈希被写进 Redis。虽然哈希不能直接反推密码，
          但 Redis 一旦泄露（未授权访问、快照文件泄露），
          攻击者拿到哈希可以离线暴力破解。
          ★ 这条在 项目说明-给AI.txt 里是已知问题 4，一直没修。

  【修法】二选一：
    a) 写缓存前 dbUser.setPasswordHash(null)
       ★ 注意：这会让方法返回的 User 也没有 passwordHash，
         需要先确认调用方有没有依赖这个字段
    b) 定义一个不含密码字段的 CacheVO，缓存和返回都用它（更干净）

  【验证】redis-cli GET user:info:1 → 返回值里不应出现 passwordHash

N3  LoginInterceptor 的空 catch 吞掉异常
--------------------------------------------------------------------------------
  位置：config/LoginInterceptor.java 游客路径的 catch 块（约 83 行）

    catch (Exception e) {
        // Token 无效，什么都不做（不打印错误，保持日志干净）
    }

  【问题】注释的理由是"保持日志干净"，但这样连"有人用伪造 token 扫描"
          都发现不了 —— 攻击行为和正常失败看着一模一样。
          ★ 这是 项目说明-给AI.txt 里的已知问题 23。

  【修法】加一行 log.debug("Token 解析失败: {}", e.getMessage())
          debug 级别不会污染正常日志，排查问题时可以临时打开。

  【验证】用一个乱码 token 请求 /novels，debug 日志里应出现这一行。

--------------------------------------------------------------------------------
  位置：service/NovelServiceIml.java

  【问题】通配符导入隐藏了"到底用了哪些类"，也让 IDE 自动导入行为不稳定。

################################################################################
  三、代码质量改进的通用思路（自己的总结）
################################################################################

【判断标准】
  · 新同事接手，能不能在 1 小时内看懂？
  · 三个月后自己回来改，还记不记得为什么这么写？
  · 有没有"这段代码删掉好像也没影响"的地方？

【三个层次的改进】
  第一层：消除明显的坏味道
    死代码、重复代码、魔法数字、硬编码、命名不规范

  第二层：提升表达力
    用异常类型表达意图（BusinessException vs RuntimeException）
    用数据结构表达约束（Hash 分组 vs 遍历查找）
    用配置表达环境差异

  第三层：用工具兜底
    静态检查（Alibaba 插件）、SonarLint、代码格式化

【最好的改进长什么样】
  "代码更短 + 性能更好 + 更安全"三者同时满足。
  比如第 3 步把两次查询合并成一次：
    原来 5 行 → 现在 2 行
    原来 2 次 DB 往返 → 现在 1 次
    原来有并发窗口 → 现在没有
