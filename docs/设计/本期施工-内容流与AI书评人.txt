  一、需求定义
################################################################################

  🎯 解决什么问题
    首页第一次有"活人"内容：访客能看到不同书评人对书的态度，
    并顺着一条书评走到正版阅读页。

  👤 谁会用
    · 访客 / 面试官：打开首页，30 秒内判断这站有没有东西可看
    · 你自己（管理员）：演示时在书详情页点「让 AI 写一篇」，现场生成

  📐 怎么算做完
    见第六节验收判据，7 条全过。

  ✂️ 为它砍掉谁
    书单、评分、关注、用户发布、阅读器改版、自动发帖、AI 读全文。
    这七项全部写进"二期"，不进本期验收。


################################################################################
  二、信息架构
################################################################################

  首页 FeedView（内容流）
    ├─ 筛选 Tab：全部 / 推荐 / 避雷        ← 长评(NOTE)只在「全部」里出现
    ├─ 书评卡片 → 点击展开全文
    ├─ 点作者头像 → 书评人主页
    └─ 点书名 → 书详情

  书详情 NovelDetailView
    ├─ 基本信息：封面 / 书名 / 作者 / 分类 / 简介
    ├─ 主按钮：去正版阅读（新窗口）
    │    └─ 没有链接时：置灰，显示「暂无正版链接」，不可点
    ├─ 书评区（Tab：全部 / 推荐 / 避雷）
    ├─ 试读入口（只有存在章节时才显示；沿用现有阅读器，不改版）
    └─ ★ 仅管理员可见：让 AI 写一篇 → 选书评人 → 生成

  书评人主页 AuthorView
    ├─ 头像 / 昵称 / AI 标识
    ├─ bio（一句话人设）/ areas（擅长领域）/ 书评数
    └─ 他写的书评列表（★ 本期没有关注按钮）


################################################################################
  三、关键流程
################################################################################

  【访客】首页 → 点卡片看全文 → 点书名 → 书详情 → 去正版阅读
    ★ 从首页到"点下阅读"是 3 步，达标。

  【管理员演示】书详情 → 点「让 AI 写一篇」→ 选书评人 → 30 秒内出现
    ★ 2 步。生成成功后：书评区立刻多一条，首页刷新能看到。

  【书评人】卡片头像 → 书评人主页 → 他写的书评列表


################################################################################
  四、页面与组件规格
################################################################################

  【4.1 书评卡片 ContentCard】
    第一行：头像 + 昵称 + AI 标识（是 AI 才显示，始终可见）
    第二行：态度徽章（推荐 / 避雷 / 长评）+ 发布时间
    第三行：标题
    第四行：正文，默认 3 行，点「展开」看全文（★ 不新建详情页）
    第五行：关联书（封面小图 + 书名，可点）
    ★ 卡片上必须能看出"这是哪本书"，否则用户走不到书详情。

  【4.2 首页内容流】
    · 每页 10 条，按发布时间倒序
    · 切 Tab 不整页刷新，只换列表
    · 空态：普通用户「还没有书评」；管理员追加「去书详情生成第一篇」
    · ★ 筛选参数全部由后端过滤，前端不拉全量再筛

  【4.3 书详情】
    · 正版按钮是页面唯一的主按钮，视觉权重最高
    · 书评区先显示 5 条 + 「查看全部」
    · 管理员操作区放在书评区上方，用低饱和的辅助样式，不要抢主按钮

  【4.4 书评人主页】
    · 顶部：头像 + 昵称 + AI 标识 + bio + areas
    · 无关注按钮、无粉丝数（follow 二期）
    · 列表复用 ContentCard

  【4.5 组件清单】
    ContentCard        书评卡片（首页 / 书详情 / 书评人主页三处复用）
    PolarityBadge      态度徽章：推荐 / 避雷 / 长评
    AiBadge            AI 标识（卡片和主页都要有，不可藏）
    CriticHeader       书评人信息头（主页与卡片复用）
    BookRef            关联书小卡（封面 + 书名，可点）
    OfficialLinkButton 去正版阅读（无链接时置灰）
    EmptyState         空态（流空 / 书无书评）
    TabBar             筛选 Tab（全部 / 推荐 / 避雷）
    复用现有：SiteHeader、SiteFooter

  【4.6 设计 token】
    沿用《前端改版-设计方案》现有 token，本批**不新增**色值 / 字号 / 圆角档位。
    只有两条语义约定：
      · 推荐 = 现有正向语义色；避雷 = 现有警示语义色；长评 = 中性色
      · AI 标识 = 中性灰底 + 小字，不抢视觉，但**不能藏在二级页面**


################################################################################
  五、数据与接口需求
################################################################################

  【5.1 字段变更（产品语言，具体建表由后端决定）】

    novel 新增两个字段：
      · 正版平台：起点 / 番茄 / 七猫 / 微信读书 / 其他（单选）
      · 正版阅读链接：一个 URL
      ★ 管理员在编辑小说时录入；没有就留空，前端走置灰降级。

    user 新增三个字段：
      · bio        一句话人设（允许写缺点，例如"只看治愈，不碰悲剧"）
      · areas      擅长领域，"悬疑,推理,犯罪"
      · is_ai      是否 AI 账号
      ★ 不要塞进登录返回的 UserVO，公开资料另走书评人接口。

    content 需要：
      作者、关联的书、态度（REC 推荐 / WARN 避雷 / NOTE 长评）、
      档位（GOD 仙草 / GOOD 粮草 / OK 干草 / BAD 毒草，可空）、
      标题、正文、发布时间、软删标记。
      ★ 是否 AI 由作者身份推导，不单独存字段，避免两处说法不一致。

    content_mark 需要：
      书评 → 标签（亮点 / 雷点 + 标签名，例如"烂尾""文笔好"）。
      ★ 本期只展示，不做筛选。

    ★ 本期**不建**：rating / booklist / booklist_item / follow / novel_pit。

  【5.2 接口需求（命名以《前端改版-设计方案》为准）】
    GET  /contents?page&size&polarity&novelId&userId&keyword
    GET  /authors/{id}                     书评人资料（含 isAi / bio / areas / 书评数）
    GET  /contents?userId={id}             某个书评人写过什么（不新建接口）
    GET  /novels/{id}                      现有详情，需补正版平台和链接
    POST /contents/generate                ★ 管理员触发生成，@RequireAdmin
    DELETE /contents/{id}                  ★ 管理员软删（内容兜底）

    ★ 列表接口三条硬要求：
      1. 批量查，禁止 N+1（作者和书的信息一次捞回）
      2. 返回 VO，不返回实体（实体会带 passwordHash）
      3. 字段名一律小写驼峰（NovelRankVO 大写首字母的坑别再踩）

  【5.3 生成规则】
    · 管理员在书详情页选一个书评人 → 触发
    · 输入：书名 / 分类 / 简介 / 可选公开片段 / 书评人 bio 与 areas
    · 输出：态度（AI 自定）+ 档位（可空）+ 标题 + 300~800 字正文 + 0~4 个标签
    · 同一书评人 + 同一本书 = 只保留一条，再生成即覆盖（避免刷屏）
    · 语气必须贴合人设；**禁止写成"我读完了全书"**，文案标「基于公开资料」
    · 生成中按钮 loading，禁止重复点击；失败不落库，返回明确错误
    · 成本护栏：单管理员 1 分钟 ≤ 3 次，每日 ≤ 20 条（复用现有 Lua 限流）

  【5.4 可选加强（+0.5 天，本期不做，随时可补）】
    定时任务：每天自动从书库按人设偏好挑一本 → 生成一篇
    · 复用同一个生成服务，不改表、不改接口
    · 面试能讲：定时任务 / 异步 / 幂等 / 重试 / token 成本控制


################################################################################
  六、验收判据（7 条全过才算做完）
################################################################################

  1. 首页首屏 ≥10 条书评，来自 ≥3 个书评人，每条都有可见 AI 标识
  2. 同一本书，能同时看到至少一条「推荐」和一条「避雷」
  3. 点卡片展开全文 → 点书名进书详情 → 点「去正版阅读」新窗口打开
     → 返回首页，列表位置不丢
  4. 管理员在书详情页点生成，30 秒内新书评出现在书详情和首页
     → 用普通账号直接调生成接口，必须返回无权限
  5. 没有正版链接的书：按钮置灰显示「暂无正版链接」，页面不崩
  6. 生成失败或超时：有明确提示，库里不多半条，页面可继续用
  7. 删掉模型 key 后：已有书评照常显示，首页和详情不白屏

  ★ 判据本身也要验：
    · 第 4 条必须用**普通账号**真的调一次接口，不能只看按钮有没有隐藏
    · 第 6 条必须**手动制造一次失败**（填错 key 或断网），看它会不会吞异常
    · 第 7 条是降级判据——它过了，才说明你想过"模型挂了怎么办"

    0–10s   首页停在一红一绿            "这本书，两个书评人意见相反。"
    10–20s  切「避雷」tab               "我把雷点摆到台面上，不是藏在低分里。"
    20–30s  点书 → 去正版阅读           "我不做渠道，只做推荐层。"
    30–40s  点作者 → 主页               "每个人有固定人设，不是每次临时生成。"
    40–60s  回书详情 → 生成一条         "这条是刚生成的，标了 AI。"

  ★ 演示别从登录页开始，从首页开始。
  ★ 现场生成失败就说"这条提前跑好了"，别卡在那。

  【已知短板（面试问到时照实答）】
    · 翻两页就到底 10~15 条  → 冷启动 + 种子策略，二期定时生成
    · 全是 AI 没有真人      → 先解决内容供给，用户发布二期
    · 不能点赞评论收藏      → 本期只读
    · 没有评分              → 用推荐/避雷比例替代一半判断
