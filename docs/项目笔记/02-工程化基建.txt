【✅ 已解决：Maven 命令行构建失败（2026-09-27）】

  【当时的现象】
    ./mvnw clean compile   →  409 行 ERROR，全是"找不到符号 getTitle()/log"

  【根因（两层）】
    第一层：JDK 版本
      · 本机 Maven 用的是 JDK 23，pom 里 <java.version>21</java.version>
        只是源码级别，不是 JDK 版本
      · JDK 23 起，javac 默认不再自动运行 classpath 上的注解处理器
      · 结果 Lombok 完全没生效，所有 getter/setter/log 都没生成
      · 为什么 IDEA 里没事：IDEA 有自己的编译配置（Lombok 插件 +
        注解处理开关），但命令行 mvn package 一定失败

    第二层（升级 JDK 25 后暴露的）：
      · 把 JDK 升到 25、pom 改成 java.version=25 之后，又报
        ExceptionInInitializerError: com.sun.tools.javac.code.TypeTag :: UNKNOWN
      · 这是 Lombok 不兼容当前 JDK 的典型报错
      · 当时 pom 里写了 <lombok.version>1.18.36</lombok.version> ——
        这个版本只支持到 JDK 24，不支持 25

  【最终修复（三处一起改才生效）】
    ① pom.xml 加 maven-compiler-plugin 的 annotationProcessorPaths
       <plugin>
         <groupId>org.apache.maven.plugins</groupId>
         <artifactId>maven-compiler-plugin</artifactId>
         <configuration>
           <proc>full</proc>
           <annotationProcessorPaths>
             <path>
               <groupId>org.projectlombok</groupId>
               <artifactId>lombok</artifactId>
               <version>${lombok.version}</version>
             </path>
           </annotationProcessorPaths>
         </configuration>
       </plugin>

    ② lombok.version 用 1.18.46（Spring Boot 4.1 管理的版本）
       ★ 不要手写更低的版本！1.18.36 不支持 JDK 25。
         最省事的做法是**不写这一行**，让 Spring Boot 的 BOM 管理。

    ③ 本机 JDK 升到 25，并确认 JAVA_HOME 生效
       ★ Windows 的环境变量修改不会传播到已运行的进程，
         改完要重启终端 / IDEA / IDE。

  【验证】
    ./mvnw clean compile   →  BUILD SUCCESS ✓
    （JDK 25 编译时有 Lombok 的 sun.misc.Unsafe 弃用警告，无害）

  ★ 实测确认：JDK 25 下编译、打包、启动全部正常
    Started Demo2Application in 5.5 seconds

  【★ 教训】
    "IDEA 能跑 ≠ 命令行能跑"。两套编译器用不同的配置。
    养成习惯：提交前跑一次 ./mvnw clean package。

【Docker 端口映射】
  docker-compose.yml：宿主机 8081 → 容器 80（因为 prod 里 server.port=80）
  MySQL：宿主机 3307 → 容器 3306

  ★★ 2026-10-08 补充：注意这个 3307 ≠ dev 用的 3306
     ------------------------------------------------------------------
     实例            地址              谁连它      表结构来源
     ------------------------------------------------------------------
     本机 MySQL      localhost:3306    dev 配置    ddl-auto=update 自动长出来
     容器 MySQL      localhost:3307    prod 配置   docker/mysql/init/01-schema.sql
     ------------------------------------------------------------------
     ⇒ **两个库完全独立**。本机 novel 表加了 author 列，
       容器里一点变化都没有 —— 这是"环境漂移"，不是没生效。
     ★ 起因：application-dev.properties 写死 3306，
             docker-compose.yml 映射到 3307，两处配置没人对账。
     ★ 教训："我明明改了但查不到" → 第一个怀疑"我连的是哪个库"。

  ★ 2026-10-08 实测：docker/mysql/init/01-schema.sql 现在是**坏的** ——
    里面有两份 mysqldump 拼接（Linux 版 + Win64 版），且**没有 bookshelf 表**。
    Bookshelf 实体已在代码里，prod 的 validate 会因为找不到表而启动失败。
