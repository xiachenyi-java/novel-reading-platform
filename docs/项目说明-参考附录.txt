################################################################################
  附 B、数据模型
################################################################################

  user
    id            INT PK AUTO_INCREMENT
    username      VARCHAR(255) NOT NULL UNIQUE
    password_hash VARCHAR(60)  NOT NULL        BCrypt
    role          VARCHAR(255) NOT NULL        默认 "USER"，管理员是 "ADMIN"

  novel
    id               INT PK AUTO_INCREMENT
    title            VARCHAR(255) NOT NULL
    author           VARCHAR(100) NOT NULL
                     ★★ 注意：库里**没有 DEFAULT '佚名'**（SHOW COLUMNS 实测 Default=NULL）
                        ⇒ 兜底只能靠 Service 层，见问题清单 19
    summary          VARCHAR(2000)
    cover_url        VARCHAR(255)
    category         VARCHAR(255) NOT NULL     自由文本，不是枚举
    status           VARCHAR(255) NOT NULL     "ONGOING" / "FINISHED"
    total_words      INT                       冗余字段（见正文决策 2）
    last_update_time DATETIME(6) NOT NULL      @PrePersist / @PreUpdate 自动维护
    索引：PRIMARY(id)
          idx_novel_last_update_time (last_update_time)
          idx_novel_category_last_update_time (category, last_update_time)

  chapter
    id             INT PK AUTO_INCREMENT
    novel_id       INT NOT NULL                手动关联，无外键约束
    chapter_number INT NOT NULL
    title          VARCHAR(255) NOT NULL
    content        LONGTEXT NOT NULL           正文，详情接口不返回
    word_count     INT NOT NULL
    create_time    DATETIME(6) NOT NULL        @PrePersist 自动填
    索引：PRIMARY(id)
          idx_chapter_novel_number (novel_id, chapter_number)

  bookshelf（软删除 + 置顶排序）
    id                   INT PK AUTO_INCREMENT
    user_id              INT NOT NULL
    novel_id             INT NOT NULL          手动关联，无外键约束
    last_read_chapter_id INT 可空              最后阅读进度
    last_read_time       DATETIME(6) 可空      最后阅读时间
    is_top               INT NOT NULL 默认 0    置顶标记
    top_time             DATETIME(6) 可空      置顶时间
    create_time          DATETIME(6) NOT NULL  @PrePersist 自动填
    update_time          DATETIME(6) NOT NULL  @PrePersist / @PreUpdate 自动维护
    deleted              INT NOT NULL 默认 0    软删除标记（移出书架不删行）
    索引：PRIMARY(id)
          uk_bookshelf_user_novel  (user_id, novel_id)          UNIQUE ★
          idx_bookshelf_top_create (user_id, deleted, is_top, top_time, create_time)
          idx_bookshelf_top_read   (user_id, deleted, is_top, top_time, last_read_time)
    ★ 唯一约束 2026-10-10 已补进库（原问题 21 已解决）
    ★ 共 4 个索引（PRIMARY + 1 UK + 2 KEY），与设计文档 1.1 节一致

  ★ 时间字段用 @PrePersist / @PreUpdate 自动维护，
    不要在 Service 里手写 setCreateTime(LocalDateTime.now())

  ★★ 表结构改动是"三处同步"，少一处就出事（详见正文 §六 常见任务入口）：
     实体类 / dev 库（ddl-auto=update 自动）/ docker 的 01-schema.sql（手工 dump）

  【统一响应格式】
    { "code": 200, "msg": "success", "data": ... }
    · code 200 = 成功，500 = 业务/系统异常
    · ★★ 业务异常返回 HTTP 200 + body code 500（团队约定，非标准 RESTful）
      ⇒ **判断成败必须看 body 的 code 字段，不能看 HTTP 状态码**
    · 401 / 403 / 429 会同时设置对应的 HTTP 状态码


################################################################################
  附 D、Redis Key 全景
################################################################################

  ------------------------------------------------------------------
  Key                            类型      TTL      用途
  ------------------------------------------------------------------
  refresh_token:{uuid}           String    7天      refreshToken → userId
  user_refresh:{userId}          String    7天      userId → refreshToken
  blacklist:user:{userId}        Hash      无★      field=token, value=过期时间戳
  user:info:{userId}             String    30分     用户信息缓存
  rate_limit:{key}:{ip}          String    window秒 限流计数
  ranking:novel:total            ZSET      无       总榜热度
  ranking:novel:day:{yyyyMMdd}   ZSET      2天      日榜热度
  progress:{userId}:{novelId}    Hash      7天      阅读进度
                                                    field: chapterId /
                                                           chapterNumber /
                                                           updateTime(毫秒)
  ------------------------------------------------------------------
  ★ blacklist 整个 Hash key 没有兜底 TTL，用户登出后不再访问就永久驻留

  【progress:* 的设计（write-behind 写回模式）】
    · 写入：NovelServiceIml.readChapter → IBookshelfService.updateProgress
            ★ readChapter 是**游客接口**，UserContext 匿名时是 null，必须判空
    · 刷回：task/ProgressFlushTask，@Scheduled(fixedDelay = 300000)
            SCAN（不是 KEYS）+ Cursor try-with-resources
            + WHERE (lastReadTime IS NULL OR lastReadTime < :readTime) 幂等
    · 为什么先写 Redis 不写 DB：快速翻页会打 10+ 次 UPDATE
    · ⚠ 移出书架时**没删这个 key** → 见问题 24
      ★ 2026-10-14：remove() 里补上了 delete(progress:...)，带 try/catch
        —— 但对**在架**记录走不到（被问题 25 的 orElseThrow 挡住）

  【Spring Cache 用的 key】（两个缓存区）
    ------------------------------------------------------------------
    缓存区          实际 key 形如              TTL       用途
    ------------------------------------------------------------------
    novel           novel::{novelId}          30 分钟   小说详情缓存
    novel-null      novel-null::{novelId}     5 分钟    防穿透：存"查过
                                                        但不存在的"标记
    ------------------------------------------------------------------
    ★ findDetail 现在用手动 cacheManager 调用读写这两个区，不再用 @Cacheable
      —— 这曾打掉缓存降级，见正文决策 7。

  【@CacheEvict 的规律 ★ 重要】
    凡是会改变 NovelDetailVO 里字段的方法，都必须加 @CacheEvict(value="novel", ...)
    NovelDetailVO 包含：id/title/summary/coverUrl/category/status/
                        totalWords/lastUpdateTime/chapters

    当前已加：
      addChapter      key = "#novelId"    （改了 totalWords 和章节列表）
      updateChapter   key = "#novelId"
      deleteChapter   key = "#novelId"
      deleteNovel     key = "#id"
      updateNovel     key = "#id"

    ★ 自查方法：写完 key = "#xxx"，回头看方法签名里有没有这个参数名。
      对不上就会 evict 一个不存在的 key，真正的缓存纹丝不动。
