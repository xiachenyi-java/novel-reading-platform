【这份文件是什么】
  一份完整的 Java 后端学习地图。从环境安装到求职面试，共 15 个阶段。

【怎么用】
  · 把它当"目录"而不是"教程" —— 每一节告诉你"要学什么"，而不是"怎么学"
  · 每学完一个阶段，去"自测题"部分检查自己是否真的掌握了
  · 不要跳阶段。第 1-4 阶段没打牢，后面全是空中楼阁

【进度标记约定】
  □ 未开始    △ 学了一半    ■ 已掌握    ★ 重点，面试必问

【三个核心原则】
  1. 代码是敲出来的，不是看出来的
     看视频 1 小时 = 自己写 20 分钟。任何知识点都要亲手敲一遍。
  2. 每学一个知识点，立刻写进项目里
     学完集合就写个"用 List 存图书"的 demo；
     学完 Spring Boot 就把 demo 改成 REST 接口。
     孤立的练习会和项目脱节，学完就忘。
  3. 不要追求"学完再开始做项目"
     第 7 阶段（Spring Boot）学完就可以开始写项目，
     后面的知识在项目里遇到再补。

################################################################################
  阶段 01 · 环境准备（3-5 天）
################################################################################

【目标】把开发环境搭起来，能跑出第一个 "Hello World"

【知识点清单】

  □ 1. 开发工具链
    ■ JDK 安装与环境变量（JAVA_HOME、PATH）
    ■ 版本选择：JDK 17 或 21（LTS 版本，不要用最新非 LTS）,现在用的25
    ■ 验证：java -version / javac -version
    ■ IDE：IntelliJ IDEA（社区版免费，够用）
        · 常用快捷键（这是效率的基础，别用鼠标点）
        · 断点调试（Step Over / Step Into / 条件断点 / 变量监视）
        · 插件：Lombok、Alibaba Java Coding Guidelines、SonarLint
    ■ 命令行基础（★ 很多新手跳过，后面吃大亏）
        · cd / ls / mkdir / rm / cp / mv / cat / grep
        · 环境变量、PATH 的含义

  ■ 2. 版本控制
    ■ Git 安装与配置（user.name / user.email / SSH Key）
    ■ 基础命令：init / clone / add / commit / push / pull
    ■ 分支：branch / checkout / merge
    ■ .gitignore 的作用
    ■ GitHub / Gitee 注册，建第一个仓库

  ■ 3. 构建工具
    ■ Maven 安装与配置（settings.xml 配阿里云镜像）
    ■ 理解 pom.xml 的作用
    ■ Maven 生命周期：clean / compile / test / package / install
    ■ 依赖坐标：groupId / artifactId / version

【练习】
  · ■ 用记事本写一个 Hello.java，用 javac 编译、java 运行
  · 用 IDEA 建一个 Maven 项目，跑出 Hello World
  · 把代码提交到 GitHub

【★ 避坑】
  · 环境变量配错是最常见的拦路虎，遇到报错先检查 JAVA_HOME
  · Maven 不配国内镜像，下载依赖会慢到崩溃
  · 不要用中文路径装 JDK 和 Maven

################################################################################
  阶段 04 · Java 核心进阶（4-5 周）
################################################################################

【目标】掌握集合框架、异常、IO、反射，能读懂框架源码里的常见写法

【知识点清单】

  □ 1. 异常体系  ★★★★
    □ Throwable → Error / Exception
    □ 受检异常 vs 运行时异常 ★
    □ try-catch-finally 的执行顺序（★ finally 里 return 会怎样）
    □ try-with-resources
    □ throw vs throws
    □ 自定义异常
    □ ★ 异常处理的四个原则（不要吞异常、不要用异常控制流程等）

  □ 2. 集合框架  ★★★★★ 面试重灾区
    □ 整体结构
        Collection → List / Set / Queue
        Map → HashMap / TreeMap / LinkedHashMap
    □ List
        · ArrayList：底层数组、扩容机制（★ 1.5 倍）
        · LinkedList：底层双向链表
        · ★ ArrayList vs LinkedList（面试必问）
        · Vector（了解，已过时）
    □ Set
        · HashSet（基于 HashMap）
        · TreeSet（基于红黑树，有序）
        · LinkedHashSet（保持插入顺序）
    □ Map  ★★★★★
        · HashMap 底层：数组 + 链表 + 红黑树
        · ★★ hash 扰动函数（为什么要高 16 位异或低 16 位）
        · ★★ 扩容机制：负载因子 0.75、扩容 2 倍、rehash
        · ★★ 树化条件：链表长度 ≥ 8 且数组长度 ≥ 64
        · ★ JDK 7 头插法导致的死循环问题
        · TreeMap：红黑树、排序
        · LinkedHashMap：保持插入/访问顺序、可实现 LRU
        · Hashtable vs HashMap（了解）
    □ 迭代器 Iterator
        · ★ fail-fast 机制（ConcurrentModificationException）
        · ★ 为什么遍历时不能直接 remove
    □ Collections 工具类
    □ ★ Comparable vs Comparator

  □ 3. 泛型  ★★★★
    □ 泛型类 / 泛型接口 / 泛型方法
    □ 类型通配符：? extends T / ? super T
        · ★ PECS 原则（Producer Extends, Consumer Super）
    □ 泛型擦除（★ 为什么不能 new T[]、不能 List<int>）
    □ 泛型在框架中的常见用法

  □ 4. IO 流  ★★★
    □ File 类
    □ 字节流：InputStream / OutputStream
    □ 字符流：Reader / Writer
    □ 缓冲流：BufferedInputStream / BufferedReader（★ 性能差异）
    □ 转换流：InputStreamReader / OutputStreamWriter
    □ 对象流：ObjectInputStream / ObjectOutputStream
        · ★ 序列化与反序列化
        · ★ serialVersionUID 的作用
        · transient 关键字
    □ BIO / NIO / AIO 的概念区别
    □ NIO 三大组件：Channel / Buffer / Selector
    □ ★ IO 多路复用（select / poll / epoll）

  □ 5. 反射  ★★★★
    □ Class 对象的三种获取方式
    □ 通过反射创建对象、调用方法、访问字段
    □ setAccessible(true) 的作用
    □ ★ 反射的性能问题与优化
    □ ★ 反射的应用：Spring 的依赖注入、MyBatis 的结果映射

  □ 6. 注解  ★★★
    □ 内置注解：@Override / @Deprecated / @SuppressWarnings
    □ 元注解：@Target / @Retention / @Documented / @Inherited
    □ 自定义注解
    □ ★ 注解 + 反射 = 框架的基石

  □ 7. 动态代理  ★★★
    □ JDK 动态代理（基于接口）
    □ CGLIB 动态代理（基于继承）
    □ ★ 两者的区别与选择（Spring AOP 的核心）

【练习】
  · 用 ArrayList 和 LinkedList 分别存 10 万条数据，比较随机访问和增删的耗时
  · 用 HashMap 统计一篇文章的词频，并按次数排序输出

################################################################################
  阶段 06 · JVM 与并发编程（4-6 周）★★★ 面试分水岭
################################################################################

【目标】理解 Java 程序的运行机制，能写出线程安全的代码
       ★ 这是后端工程师的分水岭，跳过它就只能做 CRUD

--------------------------------------------------------------------------------
6.1 JVM（2-3 周）
--------------------------------------------------------------------------------

  □ 1. 内存结构  ★★★★★
    □ 程序计数器（唯一不会 OOM 的区域）
    □ 虚拟机栈 / 本地方法栈
        · 栈帧结构：局部变量表 / 操作数栈 / 动态链接 / 返回地址
        · ★ StackOverflowError 和 OutOfMemoryError 的区别
    □ 堆
        · 新生代（Eden + Survivor0 + Survivor1）
        · 老年代
        · ★ 对象优先在 Eden 分配
    □ 方法区 / 元空间  ★（JDK 8 后从永久代改为元空间）
    □ 直接内存
    □ ★ 各区域会抛什么异常

  □ 2. 对象  ★★★
    □ 对象的创建过程（★ 五步：类加载检查 → 分配内存 →
      初始化零值 → 设置对象头 → 执行构造方法）
    □ 内存分配方式：指针碰撞 / 空闲列表
    □ ★ 内存分配并发问题（CAS + 失败重试 / TLAB）
    □ 对象的内存布局：对象头 / 实例数据 / 对齐填充
    □ 对象的访问定位：句柄 vs 直接指针

  □ 3. 垃圾回收  ★★★★★
    □ 如何判断对象已死
        · 引用计数法（★ 为什么不用：循环引用）
        · ★★ 可达性分析（GC Roots 有哪些）
    □ ★ 四种引用：强 / 软 / 弱 / 虚
    □ 垃圾回收算法
        · 标记-清除（★ 缺点：碎片）
        · 复制（★ 用于新生代，为什么）
        · 标记-整理（★ 用于老年代）
        · 分代收集
    □ 垃圾收集器
        · Serial / ParNew / Parallel Scavenge
        · ★★ CMS（并发标记清除、三色标记、浮动垃圾、Concurrent Mode Failure）
        · ★★ G1（Region、可预测停顿模型、Remembered Set）
        · ZGC / Shenandoah（超低停顿）
    □ Minor GC / Major GC / Full GC 的触发条件

    □ 每写一段业务逻辑，问自己：

        · 事务边界对吗？

  附录 A · 学习方法
################################################################################

  【★ 四个原则】
    1. 输入输出比 1:2
       看 1 小时视频，至少要写 2 小时代码。
       ★ 只看不写是学不会编程的。

    2. 费曼学习法
       学完一个知识点，试着用大白话讲给别人听。
       讲不清楚 = 没真懂。

    3. 建立知识关联
       学 Redis 的时候想："它在我的项目里能用在哪？"
       学线程池的时候想："Tomcat 处理请求用的是什么？"

    4. 允许自己"暂时不懂"
       有些原理第一遍看不懂很正常（比如 AQS、MVCC）。
       先记住结论，用起来，过一段时间再看就通了。
       ★ 不要卡在一个点上死磕三天。

  【★ 时间分配建议（每天 8 小时）】
    ------------------------------------------------------------------
    内容                          时长        说明
    ------------------------------------------------------------------
    新知识学习                    3 小时      视频 / 书籍 / 文档
    动手写代码                    3 小时      ★ 最重要
    算法题                        1 小时      每天 1-2 题
    复习 + 笔记                   1 小时      回顾昨天的内容
    ------------------------------------------------------------------

  【★ 笔记方法】
    建议按"大类"建文件夹，每个大类一个笔记文件：
      · 记录知识点（原理 + 代码示例）
      · 记录自己踩过的坑
      · 记录面试题（Q&A 形式）
      · 用版本号标记进度（A0 / A1 / A2 ...）
    ★ 笔记要能当"自己的教材"用，而不是抄一遍教科书。

  【★ 遇到问题怎么办】
    1. 先看报错信息（★ 80% 的答案在报错里）
    2. 看官方文档（最权威）
    3. 搜索引擎（关键词要准，把报错信息直接搜）
    4. AI 助手（让它解释原理，但不要让它直接给你代码）
    5. 问人（带上"我做了什么 / 期望什么 / 实际什么"）
    ★ 不要一遇到问题就问，先自己查 20 分钟。

  【★ 三个最重要的提醒】

    1. 不要追求"学完再动手"
       第 09 阶段学完就可以开始写项目，
       剩下的知识在项目里遇到再补。
       一直"准备"的人，永远开始不了。

    2. 深度比广度重要
       面试官宁愿你把 HashMap 讲透，
       也不愿意听你泛泛而谈十个框架。
       ★ 阶段 06、07 值得反复投入。

    3. 坚持比聪明重要
       每天 8 小时，坚持 6 个月，
       比"三天打鱼两天晒网"学一年效果好得多。

  祝学习顺利。
