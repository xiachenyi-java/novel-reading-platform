################################################################################
  一、先想清楚：你要的不是"能跑"，是"能运营"
################################################################################

  【两件事的区别】
    能跑   = 在你电脑上 npm run dev + IDEA 点运行
    能运营 = 别人随时能访问 + 挂了你知道 + 数据丢了能找回 + 被打能扛住

  【上线的三个判据】★ 三条全满足，才开始部署演练
    □ A  面试常问的 6 个大类到 70%+
         （01 业务 / 03 认证 / 04 限流 / 05 缓存 / 07 数据访问 / 11 测试）
         ★ 不要求 13 个大类全满，06 异步 / 10 并发 / 12 可观测性
           可以边运营边学

    ✅ B  ./mvnw test 能跑通，覆盖核心链路（12/12 连跑两遍全绿）
         ★ 没有测试就上线 = 改一行代码不知道会不会炸

    ✅ C  三个 P0 bug 全清（见 项目笔记/00-项目总览.txt 第八节）—— 已完成
         ✓ updateNovel 的 @RequestParam 改成 @PathVariable
         ✓ LoginInterceptor 非游客路径的 Redis 查询加降级
         ✓ 排行榜加降级
         ★ 为什么必须清：Redis 一挂全站 500，这不是功能问题，
           是**可用性问题** —— 上线后 Redis 抖一下，用户全跑光

  【反过来的三个"不要等"】
    ✗ 不要等 13 个大类全部 100% —— 永远不会到
    ✗ 不要等"再补一个大类"      —— 这是拖延的伪装
    ✗ 不要等功能全做完          —— 功能永远做不完（MyShelf 现在还是空壳）

  【★ 上线本身是最高效的学习方式】
    你现在学的都是"练习题"，上线后遇到的问题才是"真题"。
    详见第八节。


################################################################################
  二、阿里云选型（花小钱，别花冤枉钱）
################################################################################

  【选哪个】
    ------------------------------------------------------------------
    类型                    适合谁                你的选择
    ------------------------------------------------------------------
    轻量应用服务器          个人项目 / 学生       √ 选这个
    ECS 云服务器            企业 / 弹性伸缩        × 用不上，也更贵
    ------------------------------------------------------------------

  【配置】2 核 4G 起，不要选 2 核 2G
    理由：你要在一台机器上塞三个吃内存的东西：

      JVM      -Xmx1g                        （堆上限 1G）
      MySQL    innodb_buffer_pool_size=512M  （缓冲池 512M）
      Redis    maxmemory 256mb               （内存上限 256M）

    加起来已经约 1.8G，2G 内存的机器会开始 OOM。

    ★ 这三个数不要省。默认配置下 Spring Boot 会按物理内存的比例
      申请堆（可能拿到 1G+），MySQL 默认缓冲池 128M 偏小但也能跑，
      Redis 不设 maxmemory 会一直涨到把机器撑爆。

  【学生优惠】
    阿里云"高校计划 / 云工开物"，学生认证后百元级/年。
    ★ 价格和政策经常变，以官网当期为准，
      不要照抄任何攻略里的数字（包括这份文档）。


################################################################################
  三、ICP 备案（唯一不可压缩的一项）
################################################################################

  【为什么必须备案】
    阿里云国内节点，域名不备案，80 / 443 端口会被拦截。

  【需要什么】
    · 实名认证的域名
    · 购买时长 ≥ 3 个月的服务器
    · 身份证 + App 人脸核验
    · 各省管局要求略有差异（有的省要居住证）

  【多久】
    7-20 个工作日（各省不同，急也没用）

  【★ 关键策略：提前启动，并行等待】
    备案期间服务器照样能用，只是域名不能对外提供服务。

    所以最优解是：

      买服务器 + 买域名 + 提交备案  →  然后继续学习  →  等审批

    ★ 不要等到"代码写好了"才去买服务器，否则会出现最憋屈的情况：
      代码全好了，卡在备案上干等三周。

  【时间锚点建议】
    学习轨推进到第 4 周左右就把这件事做掉，它不占你的学习时间。

  【如果不想备案】
    可以选阿里云香港节点（免备案），但延迟高、回国带宽小，
    体验会明显变差。既然是"一直运营"，建议国内 + 备案。

  四、部署演练清单（阶段 B1）
################################################################################

  说明：每一项都要能"验证"，不要"应该没问题"。
        清单末尾有验证方法。

  ------------------------------------------------------------------
  【后端】
  ------------------------------------------------------------------
    □ Dockerfile 两阶段构建（已有）
    □ docker-compose 生产编排（已有，但要补两样：）
        □ MySQL healthcheck
              ★ 现在没有，app 会因 DB 未就绪而启动失败，
                需要手动 docker compose restart app
        □ 内存上限（mem_limit）
    □ 配置外置成环境变量：数据库密码、Redis 地址、JWT 密钥
        ★ 不要把 application-prod.properties 的真实密码提交到 git
        ★ 检查 .gitignore 有没有漏
    □ 改掉 MySQL 的 root / 123456

  ------------------------------------------------------------------
  【前端】
  ------------------------------------------------------------------
    □ npm run build
    □ Nginx 托管 dist/ + 反代 /api → 后端
        ★ Vite 的 proxy 只在 dev 生效，生产必须靠 Nginx
        ★ 别再依赖 Vite 的 rewrite，Nginx 里要重新配一遍路径规则

  ------------------------------------------------------------------
  【网络】
  ------------------------------------------------------------------
    □ 域名解析到服务器
    □ HTTPS（Let's Encrypt / certbot，配自动续期）
    □ 安全组只开 80 / 443 / 22
        ★ SSH（22）建议改端口或限制来源 IP，公网上每分钟都有人扫

  ------------------------------------------------------------------
  【图片】★ 这一项最容易被忽略，但直接影响能不能用
  ------------------------------------------------------------------
    □ 上传改 OSS

        为什么必须改：
          1 Mbps ≈ 128 KB/s
          你项目里 WebConfig 有 /uploads/** 静态映射，
          封面图直接走服务器带宽。
          一张图 200KB → 两个人同时刷列表就把带宽吃光
                       → 第三个人打开是空白页。

        怎么改：
          FileController 的逻辑不用大改，
          把"存本地磁盘"换成"传 OSS"，返回 OSS 的 URL 即可。

        ★ 这是架构级改动，不是上线当天能顺手改的，要提前排期。

    □ CDN 加速（可选，但封面图多的话强烈建议）

  ------------------------------------------------------------------
  【★ 验证方法（每一项都要亲手做一遍）】
  ------------------------------------------------------------------
    □ 用手机 4G 访问域名，能打开
        （★ 不要只在自己电脑上测 —— 你电脑能打开不代表外网能）
    □ https 能访问，http 自动跳转
    □ 上传一张图，能从 OSS 正常显示
    □ 把服务器重启一次，服务能自动起来
    ✅ ★ docker stop redis 一次（已演练 → 修复 → 2026-10-06 复测通过）
        修复前：GET /novels/{id} 挂起 60 秒 → HTTP 200 + body code=500
                （"Redis command timed out"），日志里没有降级 WARN；
                只有不依赖 Redis 的 GET /novels 列表接口不受影响。
        修复后：1.01 秒 → body code=200 + 真实数据，日志出现降级 WARN
                并发压测（500 请求 / 100 并发）：0 个超 5 秒，级联故障被切断
        （★ 修法：手动 cacheManager 调用绕过了 CacheErrorHandler，
          所以在业务代码里补 try-catch；另外必须配
          spring.data.redis.timeout / connect-timeout = 500ms，
          否则走 Lettuce 默认 60 秒，不是快速失败而是挂起）
    □ docker stop mysql 一次，看错误提示是否清晰
        （不是要它能跑，是要知道挂了长什么样）


################################################################################
  五、上线后立刻要有（阶段 B2）
################################################################################

  【没有这三样，运营会变成灾难】

  □ 1. 挂了能知道
       阿里云云监控（免费）+ 短信 / 邮件告警，监控 80 端口存活
       ★ 没有这个，你的站挂了可能三天后才知道，
         而且是从用户嘴里知道的

  □ 2. 数据能找回
       MySQL 定时备份到 OSS（每天一次，保留 7-30 天）
       ★ 没有备份的运营是赌博
         一次误删 = 全部用户数据没了，且不可逆

  □ 3. 慢了能定位
       这就是"12 可观测性"要解决的问题：
         · traceId 串联一次请求的所有日志
         · 慢接口监控（超过 N ms 打 warn）
         · 全局异常日志带堆栈
             ★ 现在兜底用 log.warn，要改成 log.error
               （"不该发生的事发生了"，见第八节问题 18）
       ★ 没有这个，用户说"很卡"，你打开日志什么都看不到，只能猜

  【日志轮转】
    已有 logback 滚动（logs/book-manager.log.*.gz）
    ★ 但要确认 maxHistory 保留天数 —— gzip 也占磁盘，
      小服务器磁盘满了一样会挂


################################################################################
  六、长期运营（阶段 B3 · 没有终点）
################################################################################

  【日常】
    □ 看告警有没有邮件 / 短信
    □ 看日志有没有异常堆积
    □ 看服务器磁盘 / 内存水位

  【内容】
    □ 发布新小说 / 章节
    □ 处理不当内容

  【用户】
    □ 回反馈
    □ 看有没有异常注册 / 登录（翻限流日志）

  【★ 续期（设日历提醒，忘了就全没了）】
    □ 服务器续费
    □ 域名续费
    □ HTTPS 证书 —— certbot 自动续期要确认真的生效了
      （很多人配了自动续期但没验证，某天早上站点就打不开了）

  【必然会发生的事（提前有心理准备）】
    · 被扫描器扫      → 正常，每分钟都有，看安全组和限流就行，别慌
    · 被爬虫爬        → 做限流，别用 IP 封，会误伤正常用户
    · 内存慢慢涨      → 观察是不是内存泄漏，这时候该学 JVM 了
    · 半夜挂掉        → 所以要告警，不要人工值守

  七、成本清单（一直运营 = 一直花钱）
################################################################################

  ------------------------------------------------------------------
  项目              周期      参考区间            说明
  ------------------------------------------------------------------
  轻量服务器        年        百元级（学生价）     2 核 4G
  域名              年        几十元               .com / .cn
  OSS 存储 + 流量   按量      几元 ~ 几十元/月     看图片数量
  CDN 流量          按量      几元 ~ 几十元/月     可选
  短信告警          按量      极少                 只在告警时发
  ------------------------------------------------------------------

  ★ 以上只是量级参考，价格经常变，以阿里云官网当期为准。

  【★ 比钱更贵的是注意力】
    一直运营意味着：毕业、找工作、上班之后，
    你的站还挂着，还需要你看。

    上班后精力会急剧下降 —— 这不是劝退，是让你心里有数。

    所以下面这些不是"可选项"，是让你以后能少操心的必需品：
      · 告警自动化（挂了自动发短信，而不是等你发现）
      · 证书自动续期（并验证真的生效）
      · 数据库自动备份（并偶尔真的去恢复一次试试）
      · 服务开机自启（服务器重启后不用你手动 docker compose up）


################################################################################
  八、和"学习轨"怎么配合（★ 双轨制的精髓）
################################################################################

  【核心机制】
    运营出的真问题  →  变成学习课题  →  做完反哺运营

  +------------------------------------------------------------------+
  | 运营现象                          该去学哪                        |
  +------------------------------------------------------------------+
  | 有人刷排行榜，数据是假的            04 限流防刷                     |
  | 用户说"很卡"但查不出原因            12 可观测性（traceId）          |
  | 服务器内存被打满 / OOM              10 并发 + JVM 内存              |
  | 热点小说缓存失效瞬间打爆 DB         05 缓存击穿                    |
  | 上传目录被塞了 .html 文件           13 安全加固                    |
  | 深夜挂了第二天才知道                12 可观测性（告警）            |
  | 发布章节很慢，用户等半天            06 异步与消息（MQ）            |
  | 想加"书架"但不知道从哪下手          01 业务功能                    |
  +------------------------------------------------------------------+

  【为什么这样学得快】
    不是"为了学而找项目练"，而是"运营真的出问题了，不得不学"。
    前者的动力是"我应该学"，后者的动力是"我的站正在挂"。

  【★ 反过来也成立：学习轨做完的东西，立刻能在运营里验证】
    比如你学完"缓存击穿"，就可以真的去压测你的热点小说接口，
    看互斥锁有没有生效 —— 这是别人在培训班里得不到的反馈闭环。

  九、常见误区（写给未来的自己）
################################################################################

  □ 误区 1：等功能全做完再上线
     → MyShelf 现在还是空壳，但没人规定书架必须有才能上线。
       上线的是"能用的最小版本"，不是"功能清单全绿"。

  □ 误区 2：等 13 个大类全 100%
     → 永远不会到。判据 A 只要求 6 个大类到 70%。

  □ 误区 3：先上线再说，安全以后补
     → 上传只校验 Content-Type（客户端可伪造）+ /uploads 匿名静态映射
       = 可以上传 .html 造成存储型 XSS。
       这条不能等，属于判据里"第一梯队"的必做项。

  □ 误区 4：上线就是终点
     → 上线是轨道 B 的起点。真正的工作从这里开始，
       真正的学习也从这里开始。

  □ 误区 5：备案可以最后再弄
     → 它是唯一"你急也没用"的事。要么提前，要么干等。

  □ 误区 6：先买便宜的低配，以后再说
     → 2 核 2G 跑 JVM + MySQL + Redis 会 OOM。
       省下的钱会变成你排查"为什么服务莫名其妙挂了"的时间。

  □ 误区 7：本地能跑就以为线上能跑
     → 本机 JDK / Redis / MySQL 都在跑，线上少一个就是 500。
       判据 C 那三个 bug 就是这么被发现的。
