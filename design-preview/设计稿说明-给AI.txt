################################################################################
  二、★ 产品设定（改代码前必须理解，否则一定做错）
################################################################################

  一句话：
  **一个「AI 和用户一起用」的小说推荐平台。**

  它跟普通小说站（起点 / 番茄）的本质区别 —— 这决定了页面结构：

   1. 内容的主角是「**推荐 / 书评 / 避雷**」，不是"书"本身
   2. **人和 AI 写的内容混在一起，首页不标注谁是 AI**；
      点进作者页才看到身份（一个很轻的「AI」描边小标）
      ★ 这是用户明确拍板的：首页标注身份会把注意力从内容引到来源
   3. **「避雷」是招牌** —— 雷点被**结构化**（烂尾 / 水字数 / 太监 /
      三观 / 开头劝退 / 后期崩 …），不是藏在低分里
   4. 评分分两块：**AI 评分 / 读者评分，分开展示**，差值本身就是内容
   5. 首页是**内容流**（刷），不是货架；书城才是货架（按分类找）
   6. 没有"今日 AI 读了多少本"这类数据看板 —— 用户不关心 AI 干了多少活


################################################################################
  三、设计规则（照着写，别自己发明新颜色）
################################################################################

  ## 颜色 —— 低饱和，克制（用户明确要求"别太炫"）
    页面底    #faf9f7      （米白，暖调）★ 注意不是纯白，也不是冷灰
    卡片底    #ffffff
    文字      #1a1a1a / #565656 / #9a9a9a / #c2c2c2  （4 档）
    分割线    #ececea（常规）/ #f4f3f1（更淡）
    主色      #6d4bd0      ★ 只用在品牌名、链接、激活态，**别大面积铺**
    推荐色    #2f8f6f  + 底 #eaf4f0
    避雷色    #b0702a  + 底 #f7efe4
    ★ 封面：一组**低饱和**的色，随机分配
        #5b6b8c / #7a6a7d / #6b7d6f / #8c7a6b / #6d6d7a / #5f7488
      —— **绝对不要用彩虹渐变**（之前出过这问题，用户不喜欢）

  ## 圆角
    卡片 12px ｜ 按钮 / 输入框 8px ｜ 胶囊标签 999px

  ## 阴影（柔和，别用过重）
    卡片：0 1px 2px rgba(20,20,20,.04), 0 8px 24px rgba(20,20,20,.05)
    hover：0 2px 6px rgba(20,20,20,.06), 0 16px 40px rgba(20,20,20,.10)

  ## 字号
    页面大标题 27px / 700 ｜ 区块标题 17px / 700
    卡片标题 15~17px / 600~700 ｜ 正文 14px ｜ 辅助 12~13px
    正文行高 1.65 ~ 1.7

  ## 顶部导航
    高 60px，白底，底边一条 1px #ececea
    品牌名「书潮」（★ 占位名，正式名未定，改的时候问一下用户）

  ## 间距
    全部用 4 的倍数（4 / 8 / 12 / 16 / 20 / 24 / 28 …）

  ★★ 重要提醒：
    项目现有的 `novel-frontend/src/styles/tokens.css` 是**紫色系**（#7c3aed），
    跟这套设计**不是一套配色**（这套主色是 #6d4bd0，且大量用米白）。
    落地时二选一：
      a) 扩 tokens.css，加一组「书潮」变量；或
      b) 新建一个 booktide.css
    **别把 #6d4bd0 到处硬编码** —— 那就退回到"改一次主色要动几十处"的老路了。


################################################################################
  四、落地到真代码：页面 → 文件 对应表
################################################################################

  ## 项目技术栈（详见 docs/前端说明-给AI.txt）
     Vue 3.5.13 + Element Plus 2.8.8 + vue-router 4 + axios + Vite
     package.json 已装 pinia，但**全项目没用 store**，状态都走 composables/
     ★ 包管理器用 npm

  ## 对应关系
    设计稿页面        现有 Vue 文件                    建议
    ------------------------------------------------------------------
    发现（内容流）    NovelListView.vue（当前是书城）   大改，或改名 FeedView.vue
    书城             NovelListView.vue 或新建          新建 StoreView.vue 更清晰
    书单             无                                新建 BookListView.vue + 新路由
    作者主页         无                                新建 AuthorView.vue + 新路由
    书籍详情         NovelDetailView.vue               改版

  ## ★ 铁律（违反会出事）
    · **不改接口契约** —— URL / 方法 / 参数名 / 返回结构一律不动。
      前端适配后端，不是反过来。
    · **不擅自加依赖** —— 图标库、UI 库、动画库，加之前必须问用户。
      能原生 CSS 解决就别引库。
    · **不擅自换技术栈 / 大重构**
    · 样式**就近放**（页面自己的 <style scoped>），不搞全局大 CSS
    · 不写行内 style（除非动态计算的值）
    · 三态齐全：**加载中 / 空数据 / 报错** 三个都要有
      ★ 设计稿**没画这三态**，落地时你必须补上
    · 响应式至少保证 375px（手机）和 1440px（桌面）不崩
    · 中文注释，写清"这块在干嘛"

  ## 别一口气全改
    **一次只落地一个页面**，先给用户看，确认了再下一个。
    建议从「发现（内容流）」开始 —— 它最能体现这个产品的设定。


################################################################################
  五、★★ 后端缺口（最重要！这些现在**根本没有**）
################################################################################

  设计稿里有一大堆东西，后端**目前完全不支持**。
  照抄前端 = 拿到空数据 = 页面空白。

  | 设计稿里的东西        | 后端现状              | 需要做什么                    |
  |----------------------|----------------------|------------------------------|
  | 推荐 / 书评 内容流     | ❌ 没有               | 新表（内容表）+ 列表/发布接口   |
  | 避雷 / 雷点清单        | ❌ 没有               | 雷点结构化（标签表 or 字段）    |
  | 书单                  | ❌ 没有               | 书单表 + 书单↔书 多对多中间表   |
  | 作者主页（含 AI 身份）  | ❌ 只有 user 表        | "作者"概念 + AI/人 身份字段     |
  | AI 评分 / 读者评分     | ❌ 没有               | 评分表 + 分开统计              |
  | 「避雷榜」            | ❌ 没有               | 按雷点/差评统计的榜单接口       |

  ## 所以怎么办
    1. **落地前端时先用假数据（mock）** —— 放在组件里或一个 mock.js 里，
       等后端接口好了再换成真调用。
    2. **这些是后端任务**。按项目规矩：**发现缺口只报告、不擅自改后端。**
       要动后端先跟用户说清楚、等他确认。

  ## 现有后端能用的（能直接接的）
    小说列表 / 详情 / 章节 / 分类 / 排行榜 / 书架 —— 见
    docs/项目说明-参考附录.txt 附 A（接口清单）

  六、已知问题 / 待办
################################################################################

  · 设计稿里所有数据都是**编的**（书名、评分、雷点评语），不是真数据
  · 「书潮」是**占位名**，正式名待定
  · 手机端（375px）适配：设计稿里写了断点，但**没有在真机上验证过**
    ★ 没有截图自检（开发时的浏览器工具挂了），落地时请务必自己跑一遍 375px
  · 设计稿没画「加载中 / 空数据 / 报错」三态 —— 落地必须补
  · 详情页的「AI 评分 vs 读者评分」、雷点清单，都是新概念，需要后端配合

  ## 之前踩过的坑（别重蹈覆辙）
    · 做过一版"细边框 + 土褐色 + 小字"的所谓简约风 → 用户评价："太土"
    · 做过一版"彩虹渐变封面 + emoji 当图标" → 用户评价："AI 味太重"
    · 正经结论：**简约 ≠ 简陋**。要"排版做到位、颜色收着来"。
